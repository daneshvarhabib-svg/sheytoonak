# What is missing before Sheytoonak is playable

Status on 2026-10-21: the repository contains gameplay C# scripts, EditMode tests, design docs, a
**placeholder prototype built entirely from code**, an editor build script, a pinned Unity version and a
GitHub Actions build workflow. The project has **never been compiled, run or built**: no C# compiler or
Unity Editor was available when the code was written (all C# files were syntax-checked only), and the
cloud build cannot run until the Unity licence secrets exist. No APK exists.

## C. Needed to build and install

| # | Item | Notes |
|---|---|---|
| 17 | Unity account + licence | Unity Personal is free below Unity's revenue threshold. Required for any build, local or cloud. |
| 18 | Build machine | The Unity Editor does not run on Android. Either a computer, or a cloud build (GitHub Actions with GameCI, or Unity Build Automation). |
| 19 | Android signing | Debug signing is enough for installing on your own phone. A release keystore is needed for Google Play. |
| 20 | iOS | Needs macOS + Xcode and an Apple Developer account to install on an iPhone. Not possible from an Android phone; a macOS cloud runner can build but signing still needs the Apple account. |

## E. Verification status (2026-10-21)

Nothing below is a Unity build. **No Unity compile, test run or Android build has happened yet.**

Verified:
- Package versions, read from the 6000.0.84f1 editor itself (GameCI image `unityci/editor:ubuntu-6000.0.84f1-base-3`):
  built-in `com.unity.test-framework` **1.6.0**, built-in `com.unity.ugui` **2.0.0**, and the Input System
  bundled with this editor is **1.20.0** (its `package.json` declares `"unity": "6000.0"`). The manifest pins
  exactly these. The previous `test-framework 1.4.5` was older than the editor's built-in version.
- Active Input Handling is **Both**, committed in `ProjectSettings/ProjectSettings.asset` (`activeInputHandler: 2`).
  The Input System 1.20.0 documentation (`use-imgui-alongside-input-system.md`) says runtime `OnGUI` gets no
  input with "Input System Package" alone, and the prototype HUD is IMGUI. The editor's API metadata has no
  public setter for this setting, so the old script workaround was removed; the build now only verifies it.
- `tools/compile-check/compile-check.sh` compiles all project assemblies (player and editor variants) with the
  editor's own C# compiler against its API assemblies, ugui 2.0.0 and Input System 1.20.0 source: all compile.
  The 23 EditMode tests pass under a minimal reflection runner. A deliberate API error makes it fail.
- GameCI: `unity-builder` v4.8.2 runs Unity through the image's `unity-editor` wrapper, which adds `-batchmode`,
  and fails the step on a nonzero Unity exit code. The test runner is pinned to v4.3.2 (results file
  `artifacts/editmode-results.xml`); the workflow fails if that file has no `Sheytoonak.Tests.*` test cases.

Still unverified (needs a real Unity run):
- Unity's own compile (asmdef resolution, the exact defines Unity adds), asset import, scene generation, IL2CPP
  and the Android player build.
- That Unity accepts the committed `ProjectSettings.asset` as is (it came from a URP template; render
  pipeline references live in other files, which are not committed).
- No `packages-lock.json`: Unity writes it on first open; commit it after the first successful CI run.
- `.meta` files are not committed; Unity generates them, so GUIDs differ between machines until committed.

## D. Deliberately not included

- No backend, accounts, online leaderboard or analytics: the first version is offline. Best score is stored on the device (`PlayerPrefs`).

# با چه ابزار/هوش مصنوعی «مدینة فاجعة» را بسازیم؟ (پژوهش، ۶ آبان ۱۴۰۵)

## خلاصه در سه خط

1. **گلوگاه مدل نیست، حلقه‌ی بازخورد است.** الان هر تغییر = کامیت → بیلد ابری ۱۰–۲۰ دقیقه‌ای Unity → نصب APK → اسکرین‌شات. نه من بازی را می‌بینم، نه تو سریع می‌بینی. هر تصویری هم که ChatGPT می‌سازد با قبلی ناسازگار است.
2. **پیشنهاد:** بازی را با **وب‌تکنولوژی (Phaser 3 + TypeScript)** بسازیم. فوراً در مرورگر گوشی باز می‌شود، من همین‌جا می‌توانم با Chromium اجرا و اسکرین‌شات بگیرم، و خروجی اندروید با **Capacitor + GitHub Actions** رایگان ساخته می‌شود.
3. **هنر و صدا** را به ابزار تخصصی بدهیم نه ChatGPT: Scenario یا Midjourney `--cref` برای ثباتِ تصویر، یک تولیدکننده‌ی اسپرایت‌شیت برای راه‌رفتن، ElevenLabs (یا مشابه) برای فحش‌های عربی.

## چرا Unity فعلی نمی‌چرخد

| مشکل | اثر |
|---|---|
| ادیتور نداریم؛ بیلد فقط در Unity Build Automation | هر تست ~۱۵ دقیقه، با توکن منقضی اصلاً نمی‌چرخد |
| من بازی را نمی‌بینم | باگ‌هایی مثل «ماشین دنده‌عقب»، «پنجره پشت پنجره» فقط با اسکرین‌شات تو پیدا می‌شوند |
| تصاویر ChatGPT بدون پس‌زمینه‌ی شفاف و بدون ثبات سبک | برش دستی، تیپ‌ها از خانه‌ای به خانه‌ی دیگر عوض می‌شود |
| اسپرایت‌های حرکتی (قدم، چرخ) نداریم | شخصیت «سر می‌خورد» |

هیچ‌کدام با عوض‌کردن مدل حل نمی‌شود؛ با عوض‌کردن زنجیره‌ی ابزار حل می‌شود.

## گزینه‌ها

### گزینه‌ی A (پیشنهادی): Phaser 3 + Capacitor + GitHub Actions
- **کد:** Phaser 3 (موتور ۲D رایگان و بالغ؛ فیزیک Arcade برای توپ کافی است). سه‌بعدی لازم نیست: بازی در عمل یک نما + توپ است.
- **اجرا:** یک صفحه‌ی HTML روی GitHub Pages؛ تو در مرورگر گوشی باز می‌کنی، من با Playwright/Chromium همین‌جا اجرا و اسکرین‌شات می‌گیرم و صدای کرش را در لاگ می‌بینم. **چرخه‌ی تست از ۱۵ دقیقه به چند ثانیه می‌رسد.**
- **اندروید:** Capacitor همان صفحه را به APK/AAB می‌پیچد؛ GitHub Actions (رایگان برای مخزن خصوصی تا ۲۰۰۰ دقیقه/ماه) بیلد می‌کند و فایل را به‌عنوان Artifact/Release می‌گذارد. امضای Play با Keystore در GitHub Secrets.
  - راهنماها: Capgo «Build Android app with GitHub Actions»، اکشن `action-capacitor-android`.
- **آنلاین/رقابت بعدی:** Supabase یا Firebase (هر دو رایگان تا حجم بالا) با همان جاوااسکریپت.
- **هزینه:** صفر. Unity و UBA هم کنار گذاشته می‌شوند.
- **ریسک:** بازی وب روی گوشی‌های ضعیف باید سبک بماند (۲D است، مشکلی نیست). WebGL داخل Capacitor همان WebView اندروید است؛ کارایی برای این بازی کافی است.

### گزینه‌ی B: ماندن روی Unity + اضافه‌کردن ادیتور واقعی
فقط اگر یک کامپیوتر (حتی موقتاً) داشته باشی معنی دارد. بدون ادیتور همان چرخه‌ی کند می‌ماند. **توصیه نمی‌شود** تا وقتی فقط گوشی هست.

### گزینه‌ی C: پلتفرم‌های «پرامپت → بازی»
| ابزار | چه می‌دهد | محدودیت |
|---|---|---|
| Rosebud AI | چت → بازی Phaser در مرورگر | خروجی اندروید ندارد (باید خودت wrap کنی)؛ کنترل کمتر روی کد |
| Summer Engine | ادعای خروجی پروژه‌ی Godot 4 | تازه، مستنداتش خودتبلیغی است |
| GDevelop | موتور بدون کد + دستیار AI، خروجی اندروید | خروجی اندروید روی پلن پولی (~۵٫۵ دلار/ماه) سهمیه‌ای است |
| Google Playground | پرامپت → بازی (آزمایشی، مهر ۱۴۰۵) | آزمایشی، خروجی اپ ندارد |
| Replit Agent | اپ موبایل + Agent + پیش‌نمایش Expo | مدل اشتراکی؛ برای بازی ۲D بی‌مزیت نسبت به A |

همه‌ی این‌ها همان مشکل را دارند: در آخر یک بازی وب تحویل می‌دهند که باید با Capacitor به APK شود. پس چرا از اول خودمان کنترل کامل را نداشته باشیم (گزینه‌ی A)؟

## هنر: ثبات و حرکت
- **ثباتِ سبک و شخصیت:** Scenario.com (آموزش سبک شخصی، اسپرایت‌شیت ۸ جهته، پس‌زمینه‌ی شفاف) یا Midjourney با `--cref` و `--sref`. ChatGPT برای تصویرِ تکی خوب است، برای «سری» نه.
- **اسپرایت‌شیت راه‌رفتن/چرخ:** Sprite Flow، Ludo.ai، Pixa، یا ابزارهای متن‌باز «sprite-sheet-creator». ورودی: یک تصویر شخصیت؛ خروجی: ۶–۸ فریم قدم.
- **پس‌زمینه:** همیشه «plain pure white background» بخواه؛ برش با رشد ناحیه (همان اسکریپتی که الان داریم) تمیز درمی‌آید.
- **هزینه:** Scenario و Midjourney پولی‌اند (از ~۱۰ دلار/ماه). **بدون تأیید تو هیچ‌کدام فعال نمی‌شود.** نسخه‌ی رایگان: Leonardo.ai (سهمیه‌ی روزانه) + ابزار متن‌باز اسپرایت.

## صدا (فحش‌های عربی)
- ElevenLabs `eleven_v3` عربی دارد، ۱۰ هزار کاراکتر/ماه رایگان؛ لهجه‌ی لبنانی تضمین نشده (باید نمونه بگیری).
- جایگزین رایگان: ضبط با گوشی از یک دوست عرب‌زبان (بهترین کیفیت لهجه) + حذف نویز.
